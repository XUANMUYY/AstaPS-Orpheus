# 第十四批「场景脚本和挑战」（fix14-script）：共用说明（每张任务卡都先读）

## 背景
- 原神私服 AstaPS（Grasscutter 分支，Java 21 + Gradle），对接国服 PC 7.1.0 客户端。
- 每张卡有**自己的 git worktree**（卡里写了路径和分支名），基线是 main `88b9edb5`。四张卡并行跑，互不影响；最后由 Claude 汇总到 `fix14-script`。
- `resources/` 和 `data/admin-catalog/` 是指向主仓的目录联接，**只读**，不要改。
- 条目来自第五轮离线盘点（静态分析）。证据里的路径前缀：`J/` = `src/main/java/emu/grasscutter/`，`S/` 和 `R/Scripts/` = `resources/Scripts/`，`R/` = `resources/`，`E/` 和 `R/ExcelBinOutput/` = `resources/ExcelBinOutput/`，`B/` = `resources/BinOutput/Quest/`，`D/` = `data/`。行号可能有偏差，以当前代码为准。

## 每个条目的做法
1. **先确认问题在当前代码上仍然存在**。已不存在的，不改，结果里写「基线上已不存在」和依据。
2. 修复要还原游戏行为，照官方数据表、场景 Lua 和客户端协议来；拿不准的地方在代码注释里写「推断」。不为某个账号特判。
3. 只改和本卡条目直接相关的文件，不做无关重构，不改格式化。`ScriptLib.java`、`SceneScriptManager.java` 是多张卡共享的文件，改动要局部（只动相关函数）。
4. 每个修复加针对性单元测试（`src/test/java/` 对应包下，参考同目录已有测试写法）。只能在游戏里看出来、确实写不了测试的，在结果里说明。
5. 编译并只跑本卡相关的测试（PowerShell，工作目录为本卡 worktree 根）：
   `.\gradlew.bat test --no-daemon --tests "<类名或包.*>"`。不要跑全量测试；不要跑会连数据库的测试（类名带 `Mongo` 的，或连 `mongodb://127.0.0.1:27017` 的）。
6. 通过后本地提交：只 `git add` 本卡改的文件（不要 `git add -A`）；提交信息用简体中文，写明条目编号（R5-xxx）和改了什么；**不要加任何 Co-Authored-By 行**（作者用仓库已配置的 XUANMUYY 身份）。不推送、不合并、不切分支、不改 git 配置。
7. 工作量大、一张卡做不完的条目：先做能让失败路径断掉的最小实现，其余写进结果。**缺协议字段定义、缺数据的不编造**：协议字段号必须能在 `protocol/7.1/`（`protocol.desc`、`compat/`）或已有生成类里核实；核实不了就跳过发包部分，写清缺什么。
