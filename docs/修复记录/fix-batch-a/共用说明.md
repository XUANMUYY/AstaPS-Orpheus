## 每个条目的做法
1. **先确认问题在当前代码上仍然存在**（上游合并可能已修）。已不存在的，不改，在结果里写「main 上已不存在」和依据。

3. 只改和本卡条目直接相关的文件，不做无关重构，不改格式化。

5. 编译并只跑本卡相关的测试：
   `.\gradlew.bat test --no-daemon --tests "<类名或包.*>"`（PowerShell，工作目录为 worktree 根）。不要跑全量测试。
   - 不要跑会连本机数据库的测试（类名带 `Mongo` 的，或连 `mongodb://127.0.0.1:27017` 的）。
6. 编译和测试通过后本地提交：
   - 只 `git add` 本卡改的文件，不要 `git add -A`。
   - 提交信息用简体中文，写明条目编号和改了什么。**不要加任何 Co-Authored-By 行**（作者用仓库已配置的 git 身份）。
   - 不推送，不合并，不切分支，不改 git 配置。
