# 官方版本更新后的行动清单

> 2026-10-25 建立。适用场景：官方原神客户端更新（大版本 x.y 或上下半卡池轮换）之后，把我们的私服跟上去。
> 原则不变：还原游戏；少做一次性工作，多做普适性工作；修复攒成大批再部署，测试清单按游戏路线分组。
> 每做完一步就在本页打勾，有新坑就补进「踩过的坑」。

## 先判断是哪种更新

| 更新类型 | 例子 | 要做的阶段 |
|---|---|---|
| **只换卡池或活动**（同一个客户端版本） | 7.1 上半 → 7.1 下半 | 第 4、5、7 阶段 |
| **小版本热更新**（客户端版本号不变或只改末位） | 资源补丁 | 第 1 阶段核对补丁，以及第 3、4、5、7 阶段 |
| **大版本更新**（例如 7.1 → 7.2） | 新地图、新主线 | 全部阶段，按顺序做 |

## 第 0 阶段：动手前

- [ ] 官服公告记下来：新版本号、上下半卡池的开放时间、UP 角色和武器、新活动和开放时间、新地图和新主线。写进 `docs/规划.md` 第 2 节。
- [ ] 私服停在旧版本继续可用，不要先动它。新版本的所有工作都在独立 worktree（`F:\Fork Reversed-worktrees\Genshin\<任务>`）里做，验证完再合并。
- [ ] 全库备份一次：沿用部署流程里的备份步骤，备份放在 `astaps-trial/backups/`。

## 第 1 阶段：客户端（只在客户端版本变化时做）

官方安装目录 `F:\miHoYo Launcher\games\Genshin Impact Game` 只读，我们用的是独立副本 `ForkClient`。

- [ ] 官方启动器更新官方客户端。
- [ ] 用 `astaps-trial/delivery/New-ForkClient.ps1` 重建 `ForkClient` 副本，做法见同目录的 `CLIENT-INTEGRATION.md`。
  - 原版的 `Astrolabe.dll` 改名为 `Astrolabe_orig.dll`，补丁 DLL 顶替原名。
  - 保留 `lunagc-patch.json`。目前默认值是：`showDamagePanel` false，`fpsUnlock` false，`fpsTarget` 60，`disableDither` false（保留官方的镜头贴近虚化）。
- [ ] **检查补丁能不能找到函数**：启动一次客户端，看 `astaps-trial/client-logs/patch.log`。
  - 每个模块都应打印地址；出现 `Failed to find xxx`，说明新版本的特征码变了。
  - 必须能找到的有：`Security`（加密密钥替换）、`Http`、`WinHttp`（请求改到本机）、`CcpBlocker`。找不到就连不上私服。
  - 可以找不到的有：`Fps`、`Misc`（关闭虚化）。找不到只是对应功能失效。
- [ ] 特征码失效时，更新 `astaps-trial/animegamepatch/src/modules/*.rs` 里的特征码，用 `build-local.cmd` 重新构建，再把 `target/release/ext.dll` 替换进 `ForkClient/YuanShen_Data/Plugins/Astrolabe.dll`。替换前先备份旧文件。这个仓库是别人的，只在本地改，不推送。
- [ ] 客户端能进登录界面、能连上本机服务端，这一阶段才算完成。

## 第 2 阶段：协议（只在客户端版本变化时做）

- [ ] 拿到新版本的协议定义和包编号映射，放到 `protocol/<版本>/`，更新 `net/packet/PacketOpcodes.java`。
  - 7.1 的映射来自 kitkat，当时有 147 个编号为 0（收发不了）。
  - 新版本要重新统计编号为 0 的包。
- [ ] 重新生成协议代码（Gradle 的协议生成任务），编译通过。
- [ ] 用 `tools/protocol/check_compatibility.py` 对比新旧协议，列出字段号变了的包。
- [ ] **重点核对已经有处理器的包**：字段号变了，处理器还能编译，但内容会解析错。7.1 的「一键购买」就是这样：请求换成了国服专用的包号 20999，服务端没有对应处理器，客户端一直转圈。
- [ ] 进游戏走一遍：登录、进大世界、打开背包、打开祈愿、打开邮件。打开 `logPackets`，把「有请求没回包」的包号收集起来，统一补处理器。

## 第 3 阶段：服务端资源

- [ ] 把 `resources/` 换成新版本的资源：`ExcelBinOutput`、`BinOutput`、`Scripts`、`TextMap`。`resources/` 本身是一个 git 仓库，切到新版本的提交即可。
- [ ] 服务端启动一次，看有没有资源加载报错（新字段、改名的枚举、找不到的文件）。
- [ ] **重跑资源导出**（`tools/resource-export/`）。导出结果写到 `data/admin-catalog/`，这个目录不进仓库，需要时重跑：
  ```bash
  python tools/resource-export/export_items.py
  python tools/resource-export/export_quests.py
  python tools/resource-export/export_gacha.py
  python tools/resource-export/export_activities.py
  python tools/resource-export/export_scene_points.py
  ```
  - 中文名对不上时，用 `_a6_textnames.py` 查新的 TextMap 来源。
  - 导出后，后台的物品、任务、卡池、活动、点位清单会自动更新。
- [ ] **任务分类和剧情跳过**：
  - 分类依据有哈希校验。资源变化后，任务调整会报「分类依据已变化」，要按 `data/quest-adjust/README-selective.md` 重新生成 `classification.json`，并检查新地区、新章节有没有归类。
  - 新主线、新世界任务：在 `classification-rules.json` 里补规则。
  - 用 `tools/quest-analysis/run_c5_locked.ps1` 重跑全剧情离线试算，对比阻断数。新出现的服务端缺口类型，按影响的主任务数排序，追加进 `docs/服务端任务缺口.md`。
  - 新的剧情脚本世界效果补到 `data/quest-adjust/world-effects.json`，新的执行项策略补到 `exec-policy.json`。
- [ ] 跑 `tools/quest-analysis/quest_deps.py`，更新任务依赖统计，看有没有新出现、服务端没实现的条件或执行项类型。

## 第 4 阶段：卡池

- [ ] 跑卡池界面扫描，看客户端里新增了哪些卡池界面编号：
  ```bash
  python tools/resource-export/export_gacha_prefabs.py --client "F:/Fork Reversed/Genshin Impact/ForkClient"
  ```
  - 它会和上次的结果对比，列出新增和消失的编号，并按「角色池、角色池2、武器池」三连号的规律推断对应关系，同时给出依据。
  - 同一个角色复刻时，官方每次都会换一个新编号，所以不能拿旧编号来推新编号。
- [ ] 按官服公告，在卡池配置 `Banners.json` 里新增本期卡池：
  - 开放时间窗；
  - UP 角色和武器；
  - prefab 编号；
  - 标题 key，用四位格式，如 `UI_GACHA_SHOW_PANEL_A0313_TITLE`；
  - 消耗道具：常驻池用相遇之缘 224，其余用纠缠之缘 223；
  - 页签顺序：角色池、角色池2、武器池、常驻池。
- [ ] 进游戏确认能显示的编号，加进 `GachaPrefabAvailable.json`。还没确认的，先借用能显示的界面，避免整个祈愿界面报「资源过期」。
- [ ] 旧卡池按时间窗自动下架，不用删除。

## 第 5 阶段：活动

- [ ] 在 `data/ActivityConfig.json` 里加入新活动和开放时间。
- [ ] 后台「公告与活动」页会标出每个活动有没有服务端玩法。「只有入口」的活动，记进 `docs/规划.md`，按用户兴趣决定要不要做。
- [ ] 功能和活动默认全开，用户在后台关闭或改时间。改动要重启服务端才生效。

## 第 6 阶段：玩家数据

- [ ] 新版本如果改了玩家存档的结构，或者官方改了获取规则，就在 `game/player/migration/PlayerDataMigrations` 里加一条版本化迁移规则。
  - 启动时会迁移所有账号，执行前备份到 `player_migration_backups`。
  - 所有账号都迁完以后，下一批部署时删掉这条规则。
- [ ] 不为单个账号写一次性脚本。

## 第 7 阶段：部署和测试

- [ ] 各 worktree 的分支合并进 main，清理 worktree。删除 worktree 前，先用 `rmdir` 拆掉里面的目录联接。
- [ ] 按部署流程走一批：
  1. 拿 `build.lock`；
  2. 全库备份；
  3. 先编译，成功后再停服；
  4. 停服前确认在线人数为 0；
  5. 启动；
  6. 核对启动日志里没有 ERROR 和 `handler_failed`；
  7. 打开包日志。
- [ ] 按游戏路线写测试清单，让用户一趟测完：
  1. 登录和大世界。
  2. 新地图：传送点、神像。
  3. 新主线：先自己玩，或者在后台「任务进度」用常用主线一键选来跳过。
  4. 祈愿：页签、标题、能不能抽、一键购买、扣哪种道具。
  5. 新活动入口。
  6. 后台各页。
- [ ] 用户测完说「测完了」，关掉包日志。
- [ ] 更新 `docs/规划.md` 和本页。

## 推送

- 只在用户说推送时才推送。
- 署名规则：大更新只署用户，不加 `Co-Authored-By`；偶尔的小修才加。

## 踩过的坑

- 编号 100 以上的卡池，标题 key 用四位格式（`A0280`）。发三位格式时，客户端会直接把 prefab 编号显示成标题。
- 常驻池用了旧版本的界面（1.x 的 A008），会导致整个祈愿界面报「资源过期」。
- 客户端补丁的 `Misc` 模块会关掉官方的镜头贴近虚化。现在默认不启用，由 `lunagc-patch.json` 的 `disableDither` 控制。
- 用 `Start-Process -ArgumentList` 传数组参数时，带空格的路径不会自动加引号。启动 Codex 时要传一整条字符串，路径用转义引号括起来。
- 任务类型名不在枚举里，会被解析成空值，整条条件被丢掉，任务就会「一碰就自动完成」。新版本新增类型时，先补枚举。
