# 服务端任务缺口（server-gaps 分支进度笔记）

来源：C5 全剧情离线 dry-run 的缺口清单 `build/quest-adjust/full-story-server-gaps.json`（69 类）。
做法：按「影响的主任务数」从大到小，把缺的 cond / exec 补进**正常游玩**的服务端逻辑（处理器 + 事件触发），
再相应放开调整引擎的阻断。状态分四级：代码完成 → 构建通过 → 已部署 → 用户验收。本分支只到「构建通过」。

## 一个通用发现（影响所有「枚举里没有名字」的类型）

任务数据按名字反序列化条件和 exec。枚举里没有的名字被 Gson 解析成 `null`，`QuestData.onLoad` 随即把整条过滤掉：

- 只带这类条件的子任务，`finishCond` 变成空数组；`LogicType.calculate` 对空进度返回 `true`，**任意事件一来就直接完成**。
- 带多条条件时，缺的那条被静默去掉，完成逻辑变了。
- exec 同理：整条 exec 消失，不报错。

所以补枚举名字本身就会改变行为：以前「意外自动完成」的子任务，现在会真的等条件满足。
本分支补了名字的类型都同时补了处理器和触发点。剩下还缺名字的类型（见下表 `missing`）仍是这个状态。
新加的枚举值是内部编号（1001 起 / exec 74），只用于服务端内部注册，不上线路。

## 需要用户进游戏验证的点

1. **机关状态变化**：找一个「把机关切到某状态」的任务步骤（例如须弥 1301601 → 1301602，机关 133302029/29003 先 0 后 201），
   操作机关后任务应推进；没操作时不应自己完成。
2. **身处指定场景**：进入副本/秘境类场景（如 1018、1009）后，对应步骤应完成；人已在场景里时接到该步骤也应立刻完成。
3. **地图分层**：枫丹（4011xx、4012xx）和其他用到分层的任务后，地图分层切换是否正常；有锁定（0）的剧情点，
   地图上那一层应消失。旧号进游戏地图分层不应比以前少。
4. **离开范围**：蒙德传说 42702（教堂附近）、45405（Q454BossFight，半径 55）这类「离开区域即失败」的步骤：
   在范围内走动不失败，跑出范围应失败并按原流程回滚；接到任务时人在远处不应立刻失败。
5. **任务全局变量**：以前「莫名其妙自动完成」的步骤（只带全局变量条件的）现在会等变量；
   重点看须弥/枫丹打工线索类任务（如 401558「四处逛逛搜寻线索」）能否正常完成，有没有卡住。
6. 进游戏后看宿主日志里有没有 `sets unknown map layer`（地图层 ID 不在表里）。

## 回退

五个提交互相独立（第 2、5 类都改了 `QuestContent` 枚举和 `QuestManager`，回退时按提交倒序）。
地图分层新增的 `Player.mapLayerUnlockStates` 字段回退后会被忽略，不需要清库。

## 合并到 main 前注意

- 本分支从 main `f15edbfc` 切出；main 工作区有未提交的 `docs/规划.md` 等文件，本分支没碰。
- worktree 用 `core.autocrlf=true` 检出时，`data/quest-adjust/classification-rules.json` 变成 CRLF，
  `QuestSelection.load` 的 SHA-256 校验会失败（`ProgressGoalTest`、`SelectiveGoalTest` 报「分类依据已变化」）。
  本分支测试时临时换回了 LF 内容，没有提交这个文件。部署目录如果是新检出的，也会遇到同样的问题。
- 新增玩家字段 `mapLayerUnlockStates`（Morphia 直接存，旧文档读出 null 已兜底）。
- 每秒一次的离开范围检查只在有活跃子任务带该条件时才发事件。
