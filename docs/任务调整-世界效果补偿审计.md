## 数据和运行口径

`data/quest-adjust/world-effects.json` 的条件键与 `InstancedScenes` 相同：`类型:param_str`（Lua 通知），其它条件为 `类型:param[0]`。exec 使用 `类型:subId`，还必须逐项匹配 `execParams`，避免同一子任务 begin/finish 同类型、不同参数被一并替代。没有条目继续走原阻断策略；审计的两个 353xx 刷怪通知没有被放行。

命中时规划 disposition 为 `world_effect_compensated`。条件补偿后继续补 Lua 进度计数；exec 命中直接应用终态，不执行原通知/刷怪 handler。除原任务流程外，补偿不杀怪发掉落、不发宝箱奖励；宝箱只出现或解锁，玩家仍需亲自领取。已死亡、已脚本移除、已开启的宝箱不会被补偿复活或重锁。

操作包括 `suites`（有序最终套件集合，第一个为主套件）、`variable`、`monsters_dead`、`remove`、`create_gadget`、`gadget_state`（仅 persistent）、`quest_progress`（持久计数至少达到目标）、`replaceable`（原组元数据必须支持）。操作可显式指定目标 group，否则沿用条目的 group。数据文件内容、证据和 `inferred` 标记全部计入策略指纹。

组未加载时只读取脚本、取得/新建缓存实例并保存，不调用 `onLoadGroup`。组已加载时通过 SceneScriptManager 的套件/实体 API 同步；先写全部死亡、变量和机关状态，再恢复套件，避免 GADGET_CREATE 回调看见中间态。这些组也纳入Lua屏障等待，屏障后核对组存档、已加载实体和动态创建机关；后续原版finishExec明确换套件时以较晚套件为准。每项操作记录 journal 前后值、证据和推断标记，撤销仍依赖整档备份。玩家不在条目场景时失败，并指出要求的场景。

组实例保存补偿套件、动态创建机关和补偿死亡怪物；重新加载时恢复，不被较早的 QuestGroupSuite 覆盖。后续真实脚本主动 RefreshGroup 时结束旧套件覆盖，原有死亡、领取和永久脚本销毁记录保留。普通未补偿组继续使用原加载路径。此处没有修正整个引擎的普通怪物刷新策略，只拦截补偿明确清除的 configId。
